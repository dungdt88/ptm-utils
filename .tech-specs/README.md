# Technical specs

One Markdown file per piece of work, describing the technical approach before it
is built. These are working documents, tied to a change rather than to the
product — the living behaviour contract is [`src/ptm/specs.md`](../src/ptm/specs.md).

Name them after the work: `monthly-rollover.md`, `recurring-tasks.md`.

A spec here typically covers: the problem, the options considered and why one
won, the shape of the change (commands, page-format impact, migration), and how
it will be tested.
